# 独立音乐提示词工作台

入口为 `http://127.0.0.1:8771/music-prompt/`，与原控制台8767分开。它导入观测、保存人工音乐目标，用规则或本机Ollama编排标签，导出音乐描述及夜莺ACE请求JSON。原蠕虫与设备采集不需要停止或修改。

## 使用

1. 用独立运行环境启动工作台与Ollama，详见 [运行说明](MUSIC-PROMPT-RUNTIME.md)。
2. 导入控制台导出的 `neural-observation-summary-v2`，或下面的音乐JSON。也可点击“已有速度标注”，只读入项目已有郎朗2003演奏的前60秒内完整拍间隔，不加载音频。
3. 选择编制、时长、目标速度和各项创作档位。“填入舒缓器乐目标”是明确的人工方案，不是对人的状态作诊断。
4. “规则预览”直接整理标签；“Ollama编排”调用本机 `qwen3:4b`，或复用身份与版本一致的本机结果。复用时显示“Ollama · 本地复用”。只有完整有效的模型结果才使用Ollama标记；模型不可用或返回不完整时显示错误。
5. 可复制英文描述、ACE JSON，或下载保留观测、目标、标签、模型digest、编排版本和输入摘要的完整JSON。新保存的完整JSON可用“导入文件”重新打开，恢复原始观测与人工目标；旧模型标记及生成文字不会被当成本次新输出，需要重新预览或编排。输入变化后旧结果会清除，并中止当前请求；推理按钮会变为“取消编排”，可手动取消。迟到的模型、文件或参考标注不会覆盖新输入。

本轮没有自动发送线上音乐生成任务。校内服务未连通，因此导出为 `remoteVerified:false`。下一阶段可在校内网络恢复后核对实际模型目录和请求合同，再接入显式生成操作。

## JSON输入

```json
{
  "schemaVersion": "music-prompt-input-v1",
  "source": {
    "id": "example-not-device-data",
    "kind": "demo"
  },
  "windowSeconds": 30,
  "music": {
    "tempo": {
      "values": [72, 74, null, 73, 72],
      "unit": "BPM"
    }
  },
  "intent": {
    "style": "solo-piano",
    "duration": 30,
    "tempoBpm": 72,
    "levels": {
      "melody": 2,
      "harmony": 1,
      "tempo": 1
    }
  }
}
```

导入上限1 MiB；UTF-8 BOM可读取。`intent` 可省略；通过文件导入时可同时填入表单。直接粘贴的JSON只读观测，创作目标由表单明确选择。`null` 表示缺失，不以0补造。

新下载的 `music-prompt-result-v1` 增加 `inputDocument`，保存支持范围内的原始输入：速度样本及其中的null、单位、来源和观察窗口；神经摘要则保留原始指数、样本数及来源时间。只保留本工作台支持的字段，未知扩展字段不写入保存输入。既有结果文件若只有统计摘要、没有 `inputDocument`，仍可用于ACE交接，但无法从均值与标准差恢复原始样本；重新导入会明确提示使用原始JSON，不补造数据。

导入新结果文件只恢复输入与通过验证的创作目标，不信任其中的旧提示词、模型身份或成功标记。输入摘要覆盖规范化后的支持字段、原始样本顺序与当前目标；两段统计相同但顺序不同的观测不会共用输入摘要。空格或未知扩展字段不属于这个摘要的含义。

允许的速度单位：`BPM`、`eighth-notes/min`、`source-beats/min`。单位原样保留。八分音符速率不自动成为生成请求的BPM；目标速度由创作表单另行确认。没有和弦、音符或谱面分析时不会根据速度或脑电补出这些事实。

已有控制台摘要保留来源、示例身份、session、记录时间、首末时间和有效覆盖。历史导入是历史记录，不能凭它判断设备此刻连接或人体此刻状态。

## 数值与档位的含义

- 速度均值与总体标准差按未平滑的有效样本计算，标准差分母是N。
- `CV = 总体标准差 / 均值`，至少3个有效样本才提供。
- 相邻变幅代理为相邻有效样本的 `|log₂(vᵢ/vᵢ₋₁)|` 均值，不跨 `null`。它是描述性代理，不等于综合音乐离散度。
- 各要素的1–5档是本项目创作控制词汇。它们不是通用学术标准，不是关注或放松指数，也未经过临床或心理效度验证。未指定的要素不添加标签。
- “力度变化”控制词是演奏目标。数字电平dBFS、MIDI velocity和谱面pp/p/f等概念保持区分，没有通过电平猜谱面力度。

## 本地模型的职责

Ollama只收到选中的固定音乐标签ID、类别及其英文短语，返回顺序；神经观测、心率、session和原始数据不进入模型。服务器拒绝同一要素的互斥档位，校验ID全排列、编制首位、录音要求末位及模型完整结束标记；浏览器另核对输入hash、标签库hash与模型身份。英文描述再由确定性编译器组装，时长、BPM和模型参数不会被模型改写。内部音乐短语的先后是语言组织选择，不是唯一音乐理论顺序。

最多32组标签排列保存在当前服务进程的内存中。只有标签集合、标签库摘要、模型digest及编排版本均一致才复用；模型身份仍会重新检查，重启后缓存清空。仅改变BPM、时长或观测时，可以复用音乐标签排列，但完整结果与ACE数值会按当前输入重新编译。下载中的 `model.cacheHit` 标明复用，`durationMs` 是本次请求耗时，`inferenceDurationMs` 是这组排列原推理耗时，`promptRevision` 标明编排版本；复用不算本次重新推理。

这是推理与受约束提示词编排，没有训练新的神经解码模型、没有微调ACE，也不能凭模型生成的句子证明脑电与音乐间的因果关系。音频是否符合提示词、是否存在底噪或具有合适音乐品质，需要实际生成和听辨。

## 标签与ACE来源

用户提供的 [AI音乐模型标签数据库及使用手册](https://docs.qq.com/doc/DRG5xRUR2eWhtcHdX) 正文自述以Suno为主要场景，更新日期2026-10-09。已读取其工作流、字段分离、提示词组合及速度、调性、旋律等相关正文。其组织方式作为参考，不将它标为脑电标注规范、官方Suno接口标准或临床标准；本项目没有复制完整数据库，标签短语为独立撰写的普通音乐表达。

ACE字段核对本机夜莺 `frontend/server/src/routes/generate.ts` 与 `tools/verify-four-model-generation-20261009.mjs`：`ditModel`、`songDescription`、`style`、`lyrics`、`instrumental`、`duration`、`bpm` 等。当前模型ID为本地代码中的 `acestep-v15-xl-sft`，不把ACE其他版本的原生API字段套到这个网站。

技术参考：

- [Ollama结构化输出](https://docs.ollama.com/capabilities/structured-outputs)：JSON Schema约束输出，程序仍独立校验含义和ID完整性。
- [Qwen3:4b官方模型条目](https://ollama.com/library/qwen3:4b)：本轮使用4B、Q4_K_M模型；模型文件大小与运行内存不同。
- [ACE-Step官方源码](https://github.com/ace-step/ACE-Step)：通用标签与描述输入；本项目线上合同以夜莺本地源代码及后续实际联调为准。
