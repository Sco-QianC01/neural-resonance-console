# 独立音乐提示词工作台

主入口为控制台蠕虫之后的“04 数据标注”：`http://127.0.0.1:8767/#annotation`。独立页面为同源 `/neural-worm/music-prompt/index.html`。流程是观测／人工标注 → 音乐标签 → 固定规则生成 Prompt → JSON交接；不调用大语言模型，不展示八小节谱面或音乐教育内容。蠕虫的图形、播放和采集逻辑不在本次改动范围。

## 使用

1. 启动原来的主控制台，进入“数据标注”，无需另起8771或Ollama。也可用 `npm start` 查看纯静态规则页面，详见[运行说明](MUSIC-PROMPT-RUNTIME.md)。
2. 可导入控制台观测摘要或下面的音乐JSON，也可直接选择音乐标签。“已有速度标注”只读取已有标注数据，不加载或播放音乐。
3. 选择编制、时长、目标速度及各项音乐标签。1–5是项目自定义创作档位，不是测量结果。“舒缓”预设是人工创作方案。
4. 点击“生成 Prompt”，固定规则直接组装英文描述，不请求语言模型。
5. 可复制提示词、ACE JSON，或下载保留输入、标注、标签及输入hash的完整JSON。下载文件可以重新导入恢复；每次修改输入会清除旧输出，需重新生成。

读入文件或已有速度标注时会清除旧输出，并暂时停用生成与导出。读取失败不会替换原输入；错误状态下不保留旧的可下载结果，检查输入后可重新生成。

本轮没有自动发送线上音乐生成任务。校内服务未连通，因此导出为 `remoteVerified:false`。下一阶段可在校内网络恢复后核对实际模型目录和请求合同，再接入显式生成操作。

## JSON输入

```json
{
  "schemaVersion": "music-prompt-input-v1",
  "source": {
    "id": "example-not-device-data",
    "kind": "demo"
  },
  "windowSeconds": 30,
  "music": {
    "tempo": {
      "values": [72, 74, null, 73, 72],
      "unit": "BPM"
    }
  },
  "intent": {
    "style": "solo-piano",
    "duration": 30,
    "tempoBpm": 72,
    "levels": {
      "melody": 2,
      "harmony": 1,
      "tempo": 1
    }
  }
}
```

导入上限1 MiB；UTF-8 BOM可读取。`intent` 可省略；通过文件导入时可同时填入表单。直接粘贴的JSON只读观测，创作目标由表单明确选择。`null` 表示缺失，不以0补造。

新下载的 `music-prompt-result-v1` 增加 `inputDocument`，保存支持范围内的原始输入：速度样本及其中的null、单位、来源和观察窗口；神经摘要则保留原始指数、样本数及来源时间。只保留本工作台支持的字段，未知扩展字段不写入保存输入。既有结果文件若只有统计摘要、没有 `inputDocument`，仍可用于ACE交接，但无法从均值与标准差恢复原始样本；重新导入会明确提示使用原始JSON，不补造数据。

导入新结果文件只恢复输入与通过验证的创作目标，不信任其中的旧提示词、模型身份或成功标记。输入摘要覆盖规范化后的支持字段、原始样本顺序与当前目标；两段统计相同但顺序不同的观测不会共用输入摘要。空格或未知扩展字段不属于这个摘要的含义。

允许的速度单位：`BPM`、`eighth-notes/min`、`source-beats/min`。单位原样保留。八分音符速率不自动成为生成请求的BPM；目标速度由创作表单另行确认。没有和弦、音符或谱面分析时不会根据速度或脑电补出这些事实。

已有控制台摘要保留来源、示例身份、session、记录时间、首末时间和有效覆盖。历史导入是历史记录，不能凭它判断设备此刻连接或人体此刻状态。

## 数值与档位的含义

- 速度均值与总体标准差按未平滑的有效样本计算，标准差分母是N。
- `CV = 总体标准差 / 均值`，至少3个有效样本才提供。
- 相邻变幅代理为相邻有效样本的 `|log₂(vᵢ/vᵢ₋₁)|` 均值，不跨 `null`。它是描述性代理，不等于综合音乐离散度。
- 各要素的1–5档是本项目创作控制词汇。它们不是通用学术标准，不是关注或放松指数，也未经过临床或心理效度验证。未指定的要素不添加标签。
- “力度变化”控制词是演奏目标。数字电平dBFS、MIDI velocity和谱面pp/p/f等概念保持区分，没有通过电平猜谱面力度。

## 规则生成

当前页面只有“生成 Prompt”一个入口。所有标签按固定目录顺序组装，编制在前、录音要求在后，再写入明确填写的目标BPM；不会请求模型健康接口或编排接口。相同标注产生相同提示词、标签顺序和ACE参数，导出时间另行记录。

导出保持 `music-prompt-result-v1`，其中 `engine:"rules"`、`model:null`；`annotations` 保留标签编号、短语与来源标识，`catalogueEvidence` 保留目录版本、SHA-256 和来源目录。摘要的编码为 UTF-8 `JSON.stringify(parsed-catalogue)`，不是文件原始字节摘要。恢复旧的模型结果文件时只读取原始输入及人工目标，旧提示词和模型成功标记不作为本次输出。输入变化后立即清除旧提示词，需重新生成。

没有在本轮新增生理指标到音乐要素的映射。观测作为来源数据独立保留，音乐标签由人选择；不把关注、放松或心率换成未经验证的音乐档位。

## 标签与ACE来源

用户提供的 [AI音乐模型标签数据库及使用手册](https://docs.qq.com/doc/DRG5xRUR2eWhtcHdX) 项目2026-10-21的记录称，曾读取其中的工作流、字段分离、提示词组合及速度、调性、旋律等正文，并记录其主要场景为Suno、更新日期为2026-10-09。其组织方式作为参考，不将它标为脑电标注规范、官方Suno接口标准或临床标准；本项目没有复制完整数据库，标签短语为独立撰写的普通音乐表达。

ACE字段核对本机夜莺 `frontend/server/src/routes/generate.ts` 与 `tools/verify-four-model-generation-20261009.mjs`：`ditModel`、`songDescription`、`style`、`lyrics`、`instrumental`、`duration`、`bpm` 等。当前模型ID为本地代码中的 `acestep-v15-xl-sft`，不把ACE其他版本的原生API字段套到这个网站。
