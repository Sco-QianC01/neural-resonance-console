# 手表实时心率

当前源码提供可选的Android手表前台采集端。无线调试在线只表示ADB连接成立；网页必须收到带设备时间和质量状态的新心率事件，才显示当前心率。

## 使用

1. 在手表开启无线调试，按Android系统界面完成配对。配对端口与连接端口可能不同；不要把配对码写入配置或日志。
2. 安装本项目构建的`NeuralResonanceWatch.apk`，打开「神经共振采集」，点击「开始采集」，在手表系统弹窗中允许身体传感器权限。
3. 保持佩戴，并让采集页面处于前台。前台采集期间屏幕保持唤醒；离开页面、停止或撤销权限时结束监听，不在后台偷偷采集。
4. 在电脑网站的「设备设置 → 手表心率」启用手表，填入已经配对的ADB连接身份，例如手表当前的`IP:连接端口`。选择本机ADB可执行文件；如果`adb`已经在PATH中，可以留空路径。
5. 保存后查看「手表心率」诊断和实际采样数。调试在线、等待权限、等待测量、有效数据、接触不可靠及断流是不同状态。

选择手表后，网站的PR通道明确采用手表心率。原有血氧设备仍可提供SpO₂；其脉率不会覆盖已选择的手表通道。取消手表选项可回到原有串口脉率来源。脑电采集、关注和放松指数始终保持独立。

## 安装和环境边界

控制台使用现有ADB入口，不启动或重启ADB服务器，不自动恢复密钥，不自动授予传感器权限，不断开其他手机。连接端口随手表重启或无线调试切换可能变化，需要在设置页更新；没有连接时不会生成替代数据。

Windows可选择已有Android platform-tools或scrcpy中的`adb.exe`。macOS需要一个可用的Android platform-tools `adb`；已有Homebrew安装的`adb`也可按其实际路径选择。不要为了安装本模块关闭Gatekeeper或SIP，也不要使用`sudo pip`或更改系统Python。控制台依赖仍按原有隔离环境安装，ADB为额外的系统工具前置条件。

本次采集端为本地测试构建，使用项目单独生成的测试签名，未使用用户或发布证书。APK声明`BODY_SENSORS`和用于本机端点的`INTERNET`权限，未申请后台身体传感器、健康历史、麦克风或定位权限；禁止把测试签名密钥提交到GitHub或打入交付包。

## 数据与隐私

数据只来自Android标准`TYPE_HEART_RATE`事件，保留bpm、设备单调时钟、原始事件时间、序号、采集会话与质量。重复轮询同一事件不会增加采样数；事件超过15秒、倒序、无效值或不可靠状态不作为当前测量。

采集端仅监听手表的回环地址。本机通过本次专用ADB转发访问，并使用采集端当前会话的临时令牌；令牌保存在采集端自己的私有目录，本机经已授权ADB读取至内存，不写网站配置、URL或日志。退出时只移除自己建立的转发。

心率不是脑电，不据此生成关注／放松指数；没有实际SpO₂或RR来源时，不生成血氧、HRV、心电或临床结论。厂商传感器清单出现ECG或PPG名称，也不等于已有可用且校准的原始流。

## 从源码构建采集端

使用已有JDK以及单独目录中的Google官方Android SDK platform 34和build-tools 35，不需要引入第三方Android运行库：

```sh
python tools/build-watch.py --sdk /path/to/isolated-sdk \
  --java-home /path/to/jdk --output artifacts/watch-apk
```

该命令生成APK、签名验证和SHA-256报告。安装时仅针对明确的手表身份：

```sh
adb -s WATCH_CONNECTION install artifacts/watch-apk/NeuralResonanceWatch.apk
adb -s WATCH_CONNECTION shell am start -n org.neuralresonance.watch/.MainActivity
```

`WATCH_CONNECTION`须替换为用户实际已配对的手表连接身份；命令不包含自动授予权限参数。

## 验收

协议测试覆盖过期、重复、倒序、错误类型、会话重启、来源隔离、临时令牌和转发清理；这些测试使用受控数据，不代表实际传感器已经工作。实机验收须另外确认手表事件推进、同一测量的网关与网页值一致、离开前台后数值清空及重连隔离。macOS逻辑测试、Windows实机数据与Mac实机数据分别记录。
