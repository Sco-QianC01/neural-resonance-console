# 旧页面启动异常修复

## 原因与范围

原有 `update()` 每100毫秒更新一次已被移除的 `sensor-pr-label`，首次运行和定时更新均会抛出空节点异常，阻断后续读数与初始化。

用户在明确获知该遗留问题后要求检查并排除bug。本次只为这个可选标签增加空值保护，沿用相邻传感器读数对缺失控件的处理；标签存在时仍按原有来源显示手表心率或脉率。不补造DOM、不恢复旧界面，不修改采集、波形计算、蠕虫设计或音频逻辑。

原有53项保护清单的哈希未改写。校验仅精确还原本次两行保护及既有第四板块路由扩展，再对照原基线；其他保护保持有效。

## 验证

- 修复前：实际渲染片段的缺节点回归失败，原生Edge出现重复空节点异常，初始化未完成。
- 修复后：263项JavaScript测试通过；26项相关Python、源码包独立构建与静态资源测试通过。
- 原生Edge：设备、波形、蠕虫三个旧入口直接启动通过，四个板块切换通过，页面无JavaScript异常。使用仓库原有静态配置，不打开硬件。
- 没有输入设备数据时，原生关注／放松保持缺失、监看封包为0，连接状态保持等待／停止。
- 数据标注的无效文件、超限文件、延迟读取、完成后下载及参考读取失败五条回归继续通过。

机器证据在本机忽略目录 `artifacts/startup-fix-20261029/`；可复用 `tools/prompt-audit.py` 与已有可选audit依赖重跑。新源码仍位于独立分支，不等同于main、原8767服务或原生发行包已更新。

## 限制

本轮验证页面启动、切页和标注交接；未进行实体设备、Mac实机、真实媒体代理、音乐播放或声学校准验收。静态预览中的媒体代理探测由测试返回404，不当作音乐模型请求或播放成功证据。
