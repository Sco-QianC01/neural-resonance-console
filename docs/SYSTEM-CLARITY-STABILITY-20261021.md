# 蠕虫与采集链路：研究核对和重整设计

日期：2026-10-21，Asia/Shanghai。状态：**设计已确认，0.11.6代码已实施；原生候选与本机替换验收已通过；硬件和Mac边界见交付报告。**

本轮先核对可视化方法和真实数据链路，再按已确认方案实施。下面现场数据为修改前快照；当前验收另见交付报告。不把界面看起来平稳当成采集可靠，不以合成数据替代实机验收。

## 1. 现场事实

本机原生包为 `0.11.5 / watch-20261020-v1`。首次检查时 8767 未监听，已核对桌面快捷方式及目标文件，并通过现有快捷方式启动。没有证据确定此前未运行的原因。

Windows Edge 检查了 1920×1080、1366×768、390×844 的音乐和神经页面。没有发现横向溢出、替换字符或 JavaScript 未捕获异常，但这不等于清晰度合格：

| 音乐蠕虫视口 | 主画布起点 | 主画布尺寸 | 问题 |
| --- | --- | --- | --- |
| 1920×1080 | 约472px | 1358×650 | 图底部及轴标落到首屏以下 |
| 1366×768 | 约472px | 840×340 | 上方操作区占用了较多高度 |
| 390×844 | 约555px | 358×350 | 首屏只能看到主图的一部分 |

这里的画布宽度包含两侧留白，不能当成实际绘图区宽度。截图见 `artifacts/system-review-20261021/`。这些是浏览器视口测试，不是实体多屏、Mac或手机验收。

在音乐蠕虫状态中，页面共有29个具有布局尺寸的按钮，手机为30个；该计数包括导航和侧栏，不表示这些按钮都在首屏，也不是学术指标。问题是入口层级和图形注意力分配，不能只靠把所有线加粗解决。

当前服务连续输出50个标准JSON心跳，历时约5.34秒，相邻到达间隔中位数约108.9ms、最大约111.5ms。所有帧的设备传输为 `none`，脑电、心率、血氧及GSR样本计数均为0。因此只能确认这段时间内“网关到浏览器的空载心跳可用”，不能给出硬件采样延迟、零丢包或长时稳定结论。

| 通道 | 现场状态 | 已证实范围 |
| --- | --- | --- |
| ThinkGear USB | 等待匹配设备 | 当前无有效脑电 |
| ThinkGear BLE | 扫描；未找到相容设备 | 当前无有效脑电 |
| AFE4490文本血氧 | 等待匹配设备 | 当前无有效血氧或脉率 |
| Android手表 | 等待已配对手表及前台采集端 | 当前无新的手表心率 |
| GSR | 未启用 | 当前没有进行实机测试 |

枚举仅见COM6、COM7两个无USB VID/PID的蓝牙串口，不能据此判定它们支持ThinkGear，更不能任意打开端口。

控制台出现一次本地音乐缓存HEAD请求404。播放器随后使用原站音频，`readyState=4`、`error=null`；这次404是可选本地副本缺失，不能直接定性为音乐无法播放。本轮没有用扬声器进行听辨验收。

## 2. 一手资料核对

本轮核读原始论文、Vmus当前公开方法和实现，以及设备和时钟文档。未取得杨健博士论文完整正文，不把专题网页的摘述写成已逐页精读论文，也不声称穷尽全网资料。

| 来源与定位 | 核对结论 | 对当前系统的约束 |
| --- | --- | --- |
| Dixon、Goebl、Widmer，2002，§3、图4及§4 | Performance Worm用速度与力度两个参数表现当前时刻和有限历史；实时显示只能使用已发生的数据 | 当前位置突出、历史衰减；显示平滑不能被写成测量更准确 |
| Dixon，2003，§4 | RMS分贝和心理声学感知响度是不同计算路径 | dBFS、来源相对振幅、sones不能互换名称；不能据此自动标注pp、mf、ff |
| Dixon等，2005，图1与§4、§6 | Air Worm把手势映射到演奏控制；作者讨论了参数简化的局限 | 人工定义的生理到音乐创作规则应标为控制规则，不称已验证的神经解码 |
| 杨健专题原站 `study.json` 的about、method | 拍点来自人工敲击和校对；速度曲线、振幅灰带与三维蠕虫有不同坐标含义；网页重算结果可能与原图注略异 | 不将多个图型混成一个“全维空间”；明确来源拍单位与计算范围 |
| Vmus `_shared/study.js` | 当前实现区分原始拍速、网格和平滑结果，并排除缺口；灰带编码相对振幅 | 同时展示时须解释各编码；灰带不是置信区间 |
| NeuroSky官方协议PDF，§2.1、§2.3及§2.4 | eSense为相对指标；0可表示无法可靠计算；接触质量有独立字段 | 不等同临床注意力、交感/副交感活动或音乐变量 |
| Python `time.monotonic`；RFC8259 §6 | 单调时钟不因系统日期校正而回拨；JSON不允许Infinity/NaN | 存活与超时用单调时间；所有外部数值必须经过有限数校验 |
| Bleak平台说明和故障排查；BrainFlow支持列表 | 平台权限、设备身份、特征和板卡协议各不相同 | 支持已识别的具体协议，不能把通用蓝牙或串口可见当成所有设备兼容 |
| Android传感器及服务文档；LSL时间同步说明 | 心率传感器权限与生命周期受系统约束；多设备时钟对齐需要额外处理 | ADB在线不是心率采集；共享屏幕时间游标不证明设备与声卡同步 |

NeuroSky网页正文入口本轮受到访问限制，使用其可读取的官方PDF及官方搜索结果核对，未绕过站点限制。

## 3. 已定位的程序问题

以下来自对现有源码和受控输入的核查，不是现场设备已经触发这些故障的声明。

| 优先级 | 位置 | 证据和影响 | 拟修复方式 |
| --- | --- | --- | --- |
| P0 | `gateway/protocols.py:95`、`gateway/acquisition.py:154` | GSR解析400位数字得到`inf`；Python序列化产生`Infinity`，浏览器标准JSON解析会拒绝整个混合包。当前GSR未启用 | 解码和通道入口拒绝非有限数；每次外发均满足标准JSON，不让一个通道污染其他通道 |
| P1 | `gateway/device_gateway.py:188` | 血氧/GSR的恢复计时依据“收到字节”，持续125秒垃圾字节仍只打开一次端口、重连0次 | 以最后有效协议包计时；字节计数只保留为诊断，不用来证明采集正常 |
| P1 | `gateway/acquisition.py:171`、`src/eeg.mjs:79`、`src/sensors.mjs:17` | 墙钟回拨可令过期值复活；前端还会拒绝时间倒退的新包，直至墙钟赶上旧值 | 保留原始墙钟用于追溯；排序、存活和持续时间改用会话内序号及单调时间 |
| P1 | `gateway/device_gateway.py:252`及退出清理；`gateway/tests/test_portable.py:153` | BLE字段3秒后已失效，但状态可在重连前继续为receiving；现有测试还要求退出后保留receiving | 分别核查连接、有效数据和过期状态；退出清理同步状态；改正测试断言 |
| P1 | `src/eeg.mjs:29`、`src/worm-model.mjs:26`、`neural-worm/planar-workbench.mjs`方法文案 | 最新Attention和Meditation可来自相差2秒的更新，却组合为一个XY点；目前“同一有效样本”措辞过强 | 新采集优先用同一协议帧中的指数对；原记录保留实际字段时间及异步配对标识，不改写为同时测量 |
| P2 | `neural-worm/planar-workbench.mjs`、`DESIGN.md`及方法文档 | 多组入口、七项并列视图、原始与显示速度、探索性代理和历史设计说明竞争注意力 | 收敛主视图和控件；高级分析折叠；确认唯一当前方法入口，历史设计继续保留并标明状态 |

“同一协议帧”也只表示同次协议报告，不自动证明设备内部两个算法在同一个ADC采样时刻计算。

已有机制应保留：唯一设备身份匹配、旧连接回调token隔离、USB/BLE切换清空旧字段、独立传感器来源、Watch事件去重、每客户端原始波形游标、有限环形缓冲、WebSocket发送超时和原始数据导出。不为本次改造重复重写这些机制。

### 丢包和延迟口径

- `rawDropped`可报告原始环形缓冲中已经被覆盖的样本，不能统计硬件尚未被解码的所有损失。
- 协议校验失败数不等于丢失样本数。一个错误协议包可能包含不同数量的样本。
- 当前USB/BLE时间戳是本机接收/处理时间，没有逐ADC样本的硬件时钟。
- 100ms是快照调度等待量，不是端到端时延上限。
- 后续没有设备时钟映射时，只报告网关后的传输指标，不给出虚构的设备到屏幕精确延迟。

## 4. 推荐重整方案

三个方向比较：

| 方向 | 收益 | 局限 |
| --- | --- | --- |
| 只改线宽和颜色 | 改动少 | 无法解决信息层级、时钟及采集状态问题 |
| **沿用现有架构，整理显示并修复链路** | 保留独立环境、真实数据和已验证适配器；直接解决本轮问题 | 需要前后端合同回归与实机确认 |
| 重写前端并引入新硬件框架 | 可建立新扩展层 | 当前没有证据证明必须，迁移范围和回归风险更大 |

推荐第二种，保留HTML/CSS/ES模块、原生本机网关和当前深色三页外壳，不新增一个平行的控制台。

### 4.1 界面信息层级

```text
共同侧栏：设备设置 / 音乐与神经响应 / 波形捕获
          实时·回放·示范、各通道状态、记录入口

研究主区域
  数据页：音乐 / 神经 / 对照
  音乐时：作品与版本选择 + 一条播放进度
  主视图：二维蠕虫 / 三维时间 / 全曲曲线 / 逐音证据
  主画布 + 当前点关键数值 + 明确单位
  折叠区：其他音乐层、版本实验、统计、方法与原始证据
```

- 全局数据模式只有一个操作入口；桥接地址、UUID、调试JSON归入设备页高级设置。
- 保留版本实验和十项音乐观测，但不再让它们与主图争夺第一层注意力。没有观测的音乐项明确缺失。
- 音乐默认进入演奏轨迹，逐音证据作为单独视图，明确现有谱面只覆盖第1–8小节。
- 保留已认可的配色和字体；不新增球体、装饰神经网络或无来源分数。
- 当前图上的原始与显示速度分别标明，主数值与主点的含义一致；另一种数值放入可展开核对。
- 手机先呈现播放、主图与当前值。1920×1080和1366×768的主图、轴名及当前点读数应可在普通视图中完整查看；精确高度在原型验收中确认。

### 4.2 二维、三维与多维对照

- 音乐二维：速度 × 来源相对振幅；按实际拍单位标记，最近10秒尾迹为建议默认值，可调整；不抹去原始拍点和缺口。
- 音乐三维：相同的速度、相对振幅，加播放时间。正交投影，视角预设可重置；轴与单位固定可见，不用大量实心平面遮挡轨迹。
- 神经二维：原生Attention × Meditation；明确是设备指标。当前点醒目，历史较淡；冻结历史时停止实时头点的视觉提示。
- 神经三维：上述两个指标加会话经过秒数。RMS只作带单位的幅度显示编码，不将光晕称为实际穿透或空间深度。
- 逐音视图：音高、记谱时值、整数小节；与速度—振幅图保持独立坐标定义。
- 对照默认采用上下对齐的小面板和同一播放游标。跨设备延迟未校准时注明；不默认用不同量纲的曲线重叠暗示等价。
- 整数小节编号与小节内位置分开，播放进度继续用时分秒。来源无可靠小节信息时使用时间，不补造小节。

### 4.3 数据合同和配对

不改写既有记录中的原始时间、来源、质量、原始波形和单位。扩展现有合同而不是删除兼容字段：

- 原始墙钟时间用于文件追溯；会话内递增序号用于消息顺序；单调时钟用于存活、计时和超时。
- 新增字段及网关重启/换源的重置规则，须一并覆盖前端、导出和回放；外部旧合同以明确的兼容策略处理。
- 各通道的最后有效事件年龄和接触质量独立。只有新的有效事件可将通道恢复为采集中。
- 新采集默认只把同一协议报告中的有效双指数对落为神经轨迹点。单项指标仍可单独显示；不为补全轨迹而复制旧值。
- 旧记录的异步配对不默默删除或重算，显示配对方法及时间差。
- 手表心率保持独立通道；没有EEG、RR或血氧来源时，相应字段保持缺失。
- 记录传输缺口、解析错误、环形缓冲覆盖及重连原因，分别统计，不合成一个“数据准确率”。

### 4.4 设备连接和独立环境

| 设备/系统 | 连接策略 | 必须保留的边界 |
| --- | --- | --- |
| 已支持的ThinkGear USB/BLE | 身份唯一且权限已授予后自动识别、验证协议、重连 | 可见设备名或串口不证明协议相容 |
| AFE4490文本血氧、已配置GSR | 有效文本解析、独立状态和恢复 | 驱动及数据格式必须匹配；不能随意打开无身份串口 |
| 当前Android手表 | 沿用明确选定的ADB入口和前台采集端，核对新事件 | 无线调试会话、权限、前台生命周期均可能影响采集；不恢复旧配对码 |
| macOS | 同源本机采集器；正确平台依赖与蓝牙授权 | 不要求Safari直接支持WebSerial/WebBluetooth；首次系统授权不能静默跳过 |
| 未知厂商/封闭手表 | 说明缺少协议、驱动或授权入口，再针对具体型号扩展 | 不宣称所有蓝牙设备都能直接提供原始EEG、RR或血氧 |

安装环境继续按每用户、每系统架构隔离；不复制Windows虚拟环境到Mac，不修改全局Python、模型路由、VPN或凭证。独立音乐提示词工作台保持现状。

本轮不自动引入BrainFlow或LSL依赖。前者的支持列表和后者的同步说明用于评估扩展与时钟边界；确有新板卡或多机同步需要时再决定适配。

## 5. 实施顺序与验收门槛

1. 修复数值边界、有效协议超时、BLE状态和时钟回拨。加入能复现上述缺陷的小测试；保留原始记录合同。
2. 统一双指数配对定义，再整理二维、三维、时间游标与当前值的显示；源切换和冻结历史不留假实时状态。
3. 收敛主页面入口，保留研究功能和证据；更新当前方法文档及设备状态说明。
4. 先在独立候选环境验证，通过后再替换本机原生包；替换前核对进程、构建、配置摘要与回滚入口。
5. 实机短测通过后，才运行长时采集和目标Mac验收；再考虑发布GitHub或安装包。

最低测试清单：

- 非有限值、极长行和错误协议包不污染其他通道；外发符合严格JSON。
- 有字节但无有效包会进入明确的恢复/等待状态；有效低频设备不被错误当成失联。
- 系统时钟前跳/回拨不复活旧数值，不长期拒绝新样本；原始时间仍可追溯。
- BLE断开、停止、权限失败、重连、迟到通知都与当前状态一致。
- 双指数异步更新不再无说明地称为同次观测；字段缺失不插值补造。
- 波形保留正负号、样本序号、缺口和单位；环形缓冲覆盖量可复核。
- 一条通道失效不会令其他有效通道消失；演示、回放和实机严格区分。
- 音乐播放、暂停、定位、换曲、2D/3D往返、视角重置和PNG/JSON/CSV导出匹配同一数据。
- 320、390、768、1366、1920、2560、3840宽度及必要DPR检查；物理扩展屏另验收。
- 真实设备插拔、睡眠唤醒、断网恢复、Mac首次权限、2小时及随后24小时运行分别记录，不能用加速模拟冒充实测时长。

发布条件：代码和协议测试、实际浏览器路径、当前设备有效样本及其导出证据分别列出。缺少某种设备时，标为待实机验收，不把该设备写成已通过。
